# Pac-Man — Ghosts! More ghosts!

## Description

A complete, playable recreation of the 1980 arcade classic **Pac-Man**,
written in Python with `pygame` and an object-oriented, modular
architecture. The player navigates a maze, eats every pacgum to clear a
level, avoids (or, after a super-pacgum, hunts) four autonomous ghosts, and
progresses through at least ten increasingly large levels while a persistent
top-ten highscore table keeps track of the best runs.

Mazes are **not** generated by us: they come from an external, assigned
*A-Maze-ing* package (`mazegenerator`) that we use as-is and adapt to.

## Instructions

Requirements: Python 3.10+ and the assigned `mazegenerator` wheel placed at
the project root.

```bash
make install        # installs pygame + the mazegenerator wheel
make run            # launches: python3 pac-man.py config.json
make debug          # runs under pdb
make lint           # flake8 . + mypy (project flags)
make lint-strict    # flake8 . + mypy --strict
make test           # runs the pytest suite
make package        # builds a distributable release (see Packaging)
make clean          # removes caches and build artefacts
```

Run manually with any JSON config:

```bash
python3 pac-man.py config.json
```

## Configuration

The config file is JSON extended with comments. Lines beginning with `#`,
`//`, and `/* ... */` blocks are stripped before parsing. Unknown keys are
ignored; missing or out-of-range values are clamped to safe defaults with a
clear log message — never a traceback.

| Key | Default | Meaning |
|-----|---------|---------|
| `highscore_filename` | `highscores.json` | Where scores are stored |
| `lives` | 3 | Starting lives (1–99) |
| `points_per_pacgum` | 10 | Score per pacgum |
| `points_per_super_pacgum` | 50 | Score per super-pacgum |
| `points_per_ghost` | 200 | Score per eaten ghost |
| `seed` | 42 | Seed for the **first** level |
| `level_max_time` | 90 | Seconds per level |
| `levels` | 10 entries | List of `{width, height}` in maze cells |

The real tile grid of a level is `(2*width+1) x (2*height+1)` after
expansion (see *Maze Generation*).

## Highscore

Highscores are stored as a small JSON array of `{ "name", "score" }`
records. We chose a plain JSON file because it is human-readable, trivial to
back up, matches the config format, and needs no external dependency. The
loader tolerates a missing or corrupted file (it starts from an empty list),
keeps only the top ten, validates names (alphanumeric + spaces, max 10
chars) and scores (non-negative integers), and is consulted at the end of
every game so the player can enter a name when they qualify.

## Maze Generation

We use the assigned `mazegenerator` package **without modifying it**. The
adapter (`src/maze_loader.py`) calls its *real* constructor — read from the
source, since the package README's quick-start is misleading:

```python
MazeGenerator(size=(width, height), perfect=False, seed=seed)
```

`PERFECT` is set to `False` to produce Pac-Man-compatible looping corridors.
The package returns a 2D `maze` list using an **edge-wall** encoding (each
cell stores its four walls in the low bits: 1=N, 2=E, 4=S, 8=W; a value of
15 is a solid block, used by the package to draw a "42"). Our loader expands
this into a classic **fat-wall** tile grid of `(2w+1) x (2h+1)`, opening a
passage tile wherever a wall bit is absent. It then finds the centre path
tile (player spawn) and the four corner path tiles (ghost spawns and
super-pacgums). If the generator is missing or fails, a `MazeError` is
raised and handled cleanly.

## Implementation

- Tile-locked entities: the player and ghosts always travel between adjacent
  tile centres, with a `progress` value interpolated for smooth rendering
  while all logic stays on integer tiles.
- Ghost AI: a greedy distance heuristic toward the player when hostile,
  away from the player (with randomness) when frightened, and back to its
  home corner when eaten.
- Super-pacgums frighten all ghosts for a few seconds; eating a frightened
  ghost scores points and sends it home.
- A central state machine drives MENU → PLAYING → (PAUSED) → GAME_OVER /
  VICTORY → ENTER_NAME → MENU.

## General Software Architecture

```
pac-man.py            entry point, argument parsing, top-level guard
config.json           default game configuration (JSON + comments)
Makefile              install / run / debug / lint / lint-strict / test / package
setup.cfg             flake8 + mypy configuration
build.sh              PyInstaller packaging script (-> dist/)
pacman.spec           PyInstaller build spec
itch_push.sh          publish the build to Itch.io via butler
itch.toml             Itch.io app manifest (bundled in the build)
INSTRUCTIONS.txt      in-package player instructions (bundled in the build)
src/
  constants.py        tile codes, colors, Direction / GameState enums
  config_loader.py    JSON-with-comments parsing, defaults, clamping
  maze_loader.py      adapter around the A-Maze-ing package
  level.py            Level model: grid + pacgums + spawns
  entities.py         MovingEntity -> Player, Ghost (+ BFS helper)
  highscore.py        persistent top-ten highscore manager
  ui.py               all pygame rendering (screens, HUD, entities)
  game.py             Game: state machine + main loop + cheats
tests/                pytest suite (config, highscore, maze, level)
project_management/   timeline, progress, risks, team, tests, retro
```

Dependencies flow one way: `game` orchestrates `level`, `entities`,
`highscore` and `ui`; `ui` only reads game state for drawing; everything
shares `constants`.

## Packaging

The game ships as a self-contained build so it can be uploaded to a public
platform (Itch.io / Steam) and launched with no Python install. The packaging
script and PyInstaller spec live at the repository root:

```bash
./build.sh          # -> dist/pac-man/ (run ./pac-man) + dist/pac-man-<os>.zip
```

`build.sh` installs the build dependencies (including the assigned
`mazegenerator` wheel, used as-is), runs PyInstaller against `pacman.spec`, and
zips the one-folder application. The build bundles `config.json`,
`INSTRUCTIONS.txt` and `itch.toml`; when started with no argument (a
double-click) the frozen build automatically loads its bundled config, so it
is fully playable on its own. Running from source still requires exactly one
`.json` argument, as the subject mandates.

To publish to Itch.io as a free, unlisted build we use
[butler](https://itch.io/docs/butler/):

```bash
ITCH_TARGET="your-user/pac-man" ./itch_push.sh
```

You may be asked to regenerate the package during the peer review — re-running
`./build.sh` reproduces it from scratch.

## Tests

A `pytest` suite under `tests/` covers the config loader (comments, clamping,
unknown keys, broken files), the highscore system (sanitising, top-10 cap,
corruption tolerance, persistence), and the maze adapter / level
(grid expansion, missing-package handling, reachability and seed
reproducibility):

```bash
make test           # or: python3 -m pytest -q
```
